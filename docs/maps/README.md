# Map tab

An interactive world map for Red/Blue through Black 2/White 2, ported from the
map viewers of **pokemap** (`A:\Dropbox\stp-projects\programs\pokemap`, the
pipeline that renders and links the maps) and the **XP router**
(`A:\pkmn_yellow_xp_router`, whose `map_data/` packs and Rust viewer this
follows). Pan and zoom the stitched overworld and every interior, toggle
marker layers, click a trainer for its party, tall grass or water for the
encounter table, and follow warps. Trainers ("Map" in the Trainers tab) and
species (the pin on a Pokédex entry) can be shown on the map from elsewhere in
the app.

## Data flow

```
pokemap pipeline (decomps / ROMs)            pokemap repo: pipeline/export-router.js
        │
        ▼
<router>/map_data/<pack>/  ← format 1 (gens 1–3: tilesets) / format 2 (gens 4–5: pre-rendered imagery.zip)
<router>/raw_pkmn_data/    ← the router's trainer tables (to match trainers)
        │   npm run build:maps        (scripts/build-maps, vite-node)
        ▼
resources/maps/<pack>.zip  ← one Solodex pack per game (gitignored, ~390 MB total)
        │   electron-builder extraResources → <install>/resources/maps
        ▼
solodex-map://<pack>/<path>   (src/main/maps: protocol over the zip)
        │
        ▼
renderer: src/renderer/src/map + components/map
```

`build:maps` turns both router formats into one Solodex format, so the viewer
has a single code path:

- **Gens 1–3** are composited at build time (`compose.ts`, a port of the
  router's `compose.rs`: CGB palettes for gen 1; per-tile palette slots, time
  of day, roofs and tileset overrides for gen 2; two-layer metatiles with
  flips for gen 3) into a lossless WebP tile pyramid for the world and one
  image per interior. Only daytime palettes are rendered.
- **Gens 4/5** copy the router's pre-rendered pyramid and interiors as they
  are. Interiors over 2048 px are re-cut into pyramids (each tile the smaller of
  lossy q92 and lossless) so the viewer never decodes a 7616 px image at once.
- Overworld sprites are extracted once per sprite × facing × palette
  (`sprites.ts`, a port of `sprites.rs`).
- Trainers are re-keyed from router names to Solodex trainer ids
  (`trainers.ts`): gen 4/5 by `rom_id`, gen 3 by `trainer_id`, gen 1 by name
  (ignoring case and spacing), gen 2 by table position. Each match is checked
  by name. The router's names add class prefixes and rematch suffixes, so a
  mismatch is reported only when neither name contains the other.
- Encounter species are mapped onto Solodex species names. Unknown ones are
  reported in `coverage.md`.

`docs/maps/coverage.md` is regenerated by every full build. It records pack
sizes, trainers placed vs. in Solodex, and anything that did not resolve. The
unplaced trainers are the ones the router has no position for either: unused
ROM entries, some rematches and battle facilities.

## Pack format

`src/shared/mapPack.ts` is the contract (types plus the mask RLE helpers). A pack
zip holds:

| Entry | Contents |
| --- | --- |
| `pack.json` | maps (steps, world position or own scope, category), surfaces, ownership grid (gen 4/5), objects, sprites, encounters by map, method/condition labels, trainer anchors |
| `terrain.bin` | one byte per 16 px step per map: `.` walk, `#` blocked, `g` grass, `w` water |
| `lift.bin` | gen 4/5: i16 per step, px the tilted render lifted the tile |
| `world/<L>/<x>_<y>.webp` | world pyramid: a level-L tile covers 512·2^L px |
| `interiors/…` | interior images, or pyramids for large ones |
| `sprites/<n>.png` | overworld sprite frames |

Coordinates are in **scope px**. The world scope is world px. An indoor map
shows in its own scope, with the map's (0, 0) at `scope.ox/oy` and its picture
at `scope.sx/sy`. Objects and steps are in 16 px steps (gen 1/2 blocks are 2×2
steps). Gen 4/5 tiles and objects are drawn `lift` px above their grid row.
Picking walks rows from the front, as the router's `pick_step` does, and in
the world only where the ownership grid gives that map the tile, because DS
map rectangles overlap.

Bump `MAP_PACK_VERSION` when the format changes. The viewer refuses a pack of
another version, and the release tag follows it (`maps-v<N>`).

## Viewer

| File | Role |
| --- | --- |
| `src/main/maps/index.ts` | `solodex-map://` protocol (zip entries, reopened when the file changes) and the `get-map-packs` IPC; `SOLODEX_MAPS_DIR` overrides the folder |
| `src/main/maps/zip.ts` | random-access zip reader (stored + deflate), shared with the build script |
| `map/pack.ts` | `useMapPack(game)` / `useMapGames()`: fetches pack.json + blobs, decodes masks, indexes objects per map and species → spots |
| `map/geom.ts` | scopes, map/step picking (lift and ownership), object/step centres, fit-to-mask (`geom.rs`) |
| `map/renderer.ts` | canvas drawing: pyramid streaming with coarser-tile fallback, masks (bilinear, soft edges), species highlight, markers / sprites, labels, focus pulse |
| `components/map/MapCanvas.tsx` | sizing, pan/zoom/drag, eased camera, click / double-click / hover |
| `components/map/MapView.tsx` | the tab: scope, layers (persisted), version, cards, focus requests, sidebar (map list, search, "Where to find") |
| `components/map/MapCards.tsx` | trainer party, encounter tables (condition chips, EVs gen 3+), map summary, item / sign / warp cards |

Keys in the Map tab: `+`/`-` zoom, `0` fits, `Esc` closes the card (then goes
back to the world), `Backspace` goes back to the world. F11 opens the tab: F10
on Windows also activates the menu bar.

## Commands

```bash
npm run build:maps                                   # every pack (≈10 min; gens 1–3 dominate)
npm run build:maps -- --games=yellow,platinum        # some packs (coverage.md is not rewritten)
npm run build:maps -- --router=<path>                # router checkout elsewhere (or SOLODEX_ROUTER_DIR)
npm run maps:publish                                 # upload resources/maps/*.zip to the maps-v<N> prerelease
npm run maps:fetch                                   # download them (the release workflow does this)
```

`npm test` covers the mask RLE (`src/shared`), the zip writer/reader and the
pyramid builder (`src/main/maps`), and the scope/picking maths (`map/geom`).

## Releasing

The release workflow runs `npm run maps:fetch` before `build:win`, so **a
`maps-v<N>` release must exist** before tagging an app release. After changing
the map data or `build:maps`, rebuild, check `coverage.md`, then
`npm run maps:publish`. The maps release is a prerelease that is never marked
latest, so the app's update check (`releases/latest`) and electron-updater
ignore it.

## Not modelled

- Gen 2 night palettes, and gen 5 seasons in the imagery. Seasonal and time-of-day
  encounter tables are shown through the condition chips.
- Route building (adding battles to a route plan) from the router's viewer, its
  ruler, marquee and PNG export, and pokemap's mask editor. Masks come resolved
  from the router packs.
- XY onwards: there are no map packs.
